Carried out phase 1: the repo installs, lints, builds, and runs a dev server on Node 22, which it could not do on any supported runtime before. The verified pairing is Node 22.14.0 with npm 10.9.2 against Gatsby 4.25, established by running each path rather than reasoning about version ranges.

- `package.json`, `.nvmrc`: `engines` moved to Node `>=22.0.0` and npm `>=10.0.0`, with `.nvmrc` pinning 22. Node 20 was rejected as the target because it left LTS maintenance in April 2026. `.npmrc`'s `engine-strict=true` stays and now does something useful: an install on Node 16 fails immediately, naming both the required and actual versions
- `eslint.config.mjs` replaces `.eslintrc.js`: ESLint 9 flat config with `eslint-plugin-react`, `eslint-plugin-react-hooks`, and `eslint-config-prettier`; nine stale lint packages including `babel-eslint` removed, and the `lint` script drops the `--ext` and `--ignore-path` flags ESLint 9 rejects. ESLint 10 was the first attempt and cannot be used yet: no released `eslint-plugin-react` accepts it, its peer range stopping at `^9.7`. `react/prop-types` is off, since it produced 279 of the first run's 306 errors and enabling it in earnest means annotating every component
- `gatsby-node.js`: strips Gatsby's own ESLint plugin from the develop bundle. Gatsby 4 injects it and reads only eslintrc-style config, so once `.eslintrc.js` was gone it fell back to its built-in rules and failed the dev bundle outright. Removing it leaves one lint authority instead of two that can disagree
- `src/components/LinkHelper/index.js`: external links were opening with `target="_blank"` and no `rel`, exposing every outbound link on the site to reverse tabnabbing; now `rel="noopener noreferrer"`, confirmed present in built HTML
- `src/hooks/useActiveId.js`: hooks ran after an early return, so hook order depended on whether the table of contents had entries; the guard moved inside the effect, which preserves the behaviour of observing nothing when the list is empty
- `src/components/Button/index.js`, `src/components/Layout/index.js`: removed duplicate `default` keys in two lookup objects (both duplicates held the same value, so no behaviour change) and a no-op `this.popOverRef;` statement whose ref is actually assigned in `render`
- Verified: `npm ci` from a deleted `node_modules` (exit 0), `gatsby build` (exit 0, 131 pages, 784 images, sitemap present), `gatsby develop` (serves, zero errors in its log), and lint running to a real baseline of 22 errors and 89 warnings, logged in `tech-debt.md`. `sharp` and `lmdb` needed no rebuild for the new Node major, since both are N-API addons
- Not verified: which Node version Netlify uses for the production build. `.nvmrc` should be picked up, but with `engine-strict=true` an older Netlify default would now fail the install instead of building on the wrong runtime, so the first deploy preview needs watching; the fallback is `NODE_VERSION` in `netlify.toml`
